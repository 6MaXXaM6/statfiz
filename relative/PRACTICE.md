# Практика по версии f2153b5: от settings до компоновки Qt

Сценарии сверены с кодом коммита `f2153b5` — `Improve demo readouts, fullscreen
layout and relative-speed theory`. Это задания для твоих правок: выполняй их
по одному, проверяй результат, затем возвращай записанный исходный фрагмент.

## Сначала учти отличия этой версии

- **Оформление находится в `ui/style.py`, внутри `app.setStyleSheet(...)`.**
  Отдельный `interface.qss` текущая версия не загружает.
- `WINDOW_TITLE`, `START_GAS_MODE`, `FIRST_PANEL`, `SECOND_PANEL` в `settings.py`
  здесь нет. Заголовок окна меняется в `main.py`, стартовые графики — в `DemoPage`.
- `SIDE_STATS_WIDTH`, `SIDE_STATS_FONT`, `GAS_PANEL_FONT`, `LEGEND_FONT`,
  `VECTOR_SIZE`, `VECTOR_MIN_SIZE` не управляют соответствующими блоками текущего
  экрана. Не трать время на увеличение этих чисел ради видимого результата.
- Среднее и дисперсия находятся в **шапке графика**. Мгновенные числа и проекция
  управляются через меню **«Вид»** и настройки `SHOW_*`.
- У размера сосуда есть свой расчёт `_fit_box()`; после F11 он повторяется через
  таймер и фильтр событий. Изменение одного stretch не отменяет фиксированную ширину.

## Как тренироваться

Запуск из корня проекта `statfiz`:

```sh
make -C relative run
```

Меняешь исходник → сохраняешь → закрываешь приложение → запускаешь снова.
Уже открытая страница сама Python-файл не перечитывает. Старый exe тоже не обновляется.
Перед каждым упражнением записывай исходные строки в черновик, чтобы вернуть
именно свою правку, сохранив остальную работу.
Сохраняй отступы Python: у метода внутри класса перед `def` четыре пробела,
у его тела — восемь. Фрагменты показывают содержимое для соответствующего места.

Для проверки компоновки после перемещения блоков:

```sh
make -C relative layout
```

Открой опыт и дополнительно проверь окно, F11, выход из полного экрана и уменьшение
окна. Автопроверка не заменяет осмотр главной страницы, авторов и теории.

## 1. Запуск при 600 К, с 80 частицами и без автостарта

**Где:** [settings.py](settings.py).

Замени существующие значения:

```python

START_N = 80
AUTOSTART = False
```

**Проверка:** после перезапуска открой опыт. Поля показывают T=600 и N=80,
движения нет до нажатия Старт. Старт создаёт газ с этими параметрами.

**Что сказать:** «Experiment читает значения, создаёт Gas. GasPanel показывает
параметры модели. AUTOSTART управляет автоматическим стартом, а не физикой ударов».

`START_N_B` — число B внутри общего N; смесь включается кнопкой интерфейса.
Примеры теории имеют собственные стартовые 300 К — эта правка их не меняет.

## 2. Реже обновлять графики на слабом ноутбуке

**Где:** [settings.py](settings.py).

Бюджет порции задаёт `FAST_BUDGET` в секундах. Эта правка — изменение целевых
интервалов, а не доказанный замером прирост производительности.


В конце `MainWindow.__init__`, после создания `self.font_scale`:

```python
self.pause_shortcut = QtWidgets.QShortcut(QtGui.QKeySequence('Space'), self)
self.pause_shortcut.activated.connect(self.toggle_demo_pause)
```

Новый метод `MainWindow`:

```python
def toggle_demo_pause(self):
    if self.stack.currentWidget() is self.demo:
        self.demo.run.toggle_pause()
```

**Проверка:** активный опыт running → пробел → paused → пробел → running.
На главной и в теории скрытый расчёт не запускается. В состоянии Стоп пробел
ничего не делает: `toggle_pause` работает только с running/paused.

**Что сказать:** «QShortcut выдаёт activated, обработчик проверяет страницу и
использует существующий автомат состояний. QShortcut сам не двигает частицы».

## 21. Сдвинуть построение векторов внутри сосуда

**Вероятное задание:** «Перенесите блок, где складываются векторы скоростей,
из нижнего левого угла в верхний правый».

Это **не перенос всего сосуда** из сценария 11. Три стрелки построения — объект
`VectorView` в общей графической сцене, а цветная подпись под ними — отдельный `QLabel`.
Стрелки, прикреплённые к самим молекулам, — ещё другие объекты; они должны оставаться у частиц.

### А. Переместить только треугольник стрелок

**Открываешь:** [ui/plots/box_view.py](ui/plots/box_view.py), метод `place_vectors`.
Найди существующий якорь:

```python
anchor = QtCore.QPointF(vessel.left() + .22 * vessel.width(),
                       area.bottom() - .22 * vessel.height())
```

**Замени только его вычисление:**

```python
anchor = QtCore.QPointF(
    vessel.left() + .75 * vessel.width(),
    area.top() + .25 * area.height(),
)
```

Оставь существующий вызов `self.vector_overlay.set_area(area, anchor)` ниже.

- `vessel` — прямоугольник сосуда в координатах сцены.
- `area` — доступная область для стрелок; место для подписи уже исключено.
- `.75` по x — предпочитаемая позиция ближе к правому краю.
- `.25` по y — ближе к верху доступной области. Экранная y растёт вниз.
- `anchor` — желаемая позиция общего начала красной и синей стрелок.

**Варианты для той же новой формулы:**

| Куда просят | Коэффициент x | Коэффициент y |
|---|---:|---:|
| Влево вверх | `.25` | `.25` |
| Вправо вверх | `.75` | `.25` |
| Примерно в центр | `.50` | `.50` |
| Влево вниз | `.25` | `.75` |
| Вправо вниз | `.75` | `.75` |

Если просят небольшой сдвиг от выбранного места, после вычисления anchor можно добавить:

```python
anchor += QtCore.QPointF(20, -15)
```

Это желаемый сдвиг вправо на 20 единиц сцены и вверх на 15. Здесь это координаты
рисования, **не нм координат молекул и не м/с скорости**.

**Проверка:** поставь опыт на паузу, сравни положение построения до/после перезапуска,
затем продолжи расчёт. Измени размер окна, F11 туда-обратно, температуру и выбранную пару.
Цвета, длины векторов и формула vотн = v₁ − v₂ остаются прежними; стрелки у частиц
не должны переехать в угол вместе с построением. Подпись в варианте А остаётся внизу.

**Важное ограничение:** anchor — предпочитаемая точка, не безусловный приказ.
`VectorView._place()` сдвигает построение внутрь допустимой области, если оно
иначе вылезает за край. Поэтому при длинных стрелках положение может отличаться
от выбранной четверти. Если целое построение слишком велико, оно скрывается;
масштаб автоматически не уменьшается. Для наглядной проверки выбери умеренные скорости.

**Что сказать:** «Построение — графический объект, а не отдельное окно Qt.
BoxView вычисляет якорь по размеру сосуда, VectorView размещает группу целиком
и учитывает её границы. Меняю привязку в place_vectors, чтобы она переживала resize».

Разовый `self.vectors.setPos(...)` в конструкторе будет позже перезаписан `_place()`.
Метода QWidget.move() у этой группы вообще нет: это QGraphicsObject.

### Б. Если просят перенести и цветную подпись наверх

В том же `place_vectors` после строки вычисления `caption_height` замени участок
**от `x = ...` до вычисления `anchor` включительно** следующим блоком:

```python
x = max(area.left(), vessel.left() + margin)
top = max(area.top(), vessel.top() + margin)
self.vector_caption.setGeometry(
    round(x), round(top),
    max(1, round(area.right() - x)), caption_height,
)
# Резервируем верхнюю строку: стрелки не должны заходить на подпись.
area.setTop(top + caption_height + margin)
anchor = QtCore.QPointF(
    vessel.left() + .75 * vessel.width(),
    area.top() + .25 * area.height(),
)
```

Это **замена**, а не дополнение к старым `bottom = ...` / `area.setBottom(...)`.
Остальной хвост метода — пересчёт масштаба, `set_area`, `raise_` и проверку стрелок
частиц — сохрани.

**Проверка:** подпись стала верхней строкой над областью построения. Стрелки
не пересекают её текст. Проверь также проекцию через меню «Вид»: подпись может
содержать две строки. Скрытие/показ построения всё ещё работает.

**Что сказать:** «Подпись и группа стрелок — разные объекты. Перенёс QLabel
и исключил занимаемую им верхнюю полосу из допустимой области стрелок.
Если перенести только текст, стрелки могут на него наложиться».

## Как быстро проверить себя после каждого упражнения

- **Настройка/цвет:** перезапуск и осмотр конкретного элемента.
- **Перемещение/шрифт:** осмотр, уменьшение окна, F11 туда-обратно, `make -C relative layout`.
- **Новый обработчик:** проверка действия на паузе, при расчёте и на другой странице.
- **Изменение принятого поведения:** `make -C relative test`, разбор отличий от прежних ожиданий.

Часть тестов специально фиксирует начальные значения, формат и положение статистики.
Временные учебные правки возвращай к исходным перед проверкой исходного контракта.
Если изменение остаётся в приложении, обновляй связанные ожидания, сохраняя
проверки правильности чисел, сигналов и отсутствия сброса данных.

На вопрос «почему не двигаете всё через move?» отвечай:
**«Верхнеуровневое окно можно позиционировать. Внутренние элементы размещает
layout, поэтому меняю порядок, направление, stretch, spacing и ограничения размеров».**
